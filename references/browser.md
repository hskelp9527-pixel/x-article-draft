# 浏览器路线（宿主 Agent 执行）

本 Skill 提供路径解析和转换；浏览器动作由宿主实际提供的工具执行。不要将 `save --method browser` 误认为完整无人值守 CLI：它返回 `browser_action_required`，需要 Agent 接着执行本页。

## 打开与准备

- 遵守宿主浏览器工具的使用说明。复用用户选择的真实 Chrome 与持久登录态；不导出 Cookie。无浏览器控制能力时说明限制，转 API 须由用户选择。
- 打开 https://x.com/compose/articles ，核对当前账号是否正确以及有无 Articles 编辑权限。使用页面的实时元素，不凭历史坐标点击。
- 读取 `prepare` 返回的 `article.json` 和 `body.html`。manifest 包含标题、封面、正文图片按序排列的 `placeholder` 和已解析的绝对 `path`。这些路径是运行时私有数据。
- 先检查草稿列表；如同一标题已存在，打开检查。相同内容就复用；内容不同且不清楚是否覆盖时让用户选择。不要仅凭标题覆盖别人已有的草稿。

## 填入长文章

1. 创建草稿，填写 manifest 的 title。若有 cover，使用当前编辑器的封面上传入口选择其 path。
2. 将 body.html 作为 **富文本 HTML** 复制到系统剪贴板，使用真实粘贴操作放入正文。优先使用宿主原生支持的富文本剪贴板能力；也可执行 `node "{baseDir}/scripts/clipboard.mjs" "<body.html>"`，随后由浏览器工具真实按 Ctrl+V（macOS 为 Meta+V）。此辅助程序支持 Windows CF_HTML、macOS osascript，以及安装了 wl-copy/xclip 的 Linux 图形会话。只有 CF_HTML 字节偏移算法已单元验证，各系统的实际剪贴板/浏览器粘贴仍需验收。不得将 HTML 源码直接输入编辑器，不能只用 Set-Clipboard 文本冒充富文本。若宿主只支持纯文本且辅助程序不可用，说明当前不能保留格式，不能悄悄降级。
3. 对每个正文图片，定位对应占位符（例如 `XIMGPH_0`）的准确位置。使用 X 编辑器的 Insert → Media（或当前语言对应项），在媒体弹窗点实际的文件上传入口，选择 manifest 的本地 path。上传后删除原占位符，检查图片仍处于原段落之间。不要依赖 `<img src="file:///...">` 或 HTML 粘贴自动上传本地图片。
4. 以页面实际控件为准，确认图片上传完成。若文件选择权限被宿主拦截，按该工具自己的文档修复；不要绕过权限或改用未获授权的方式。第一张图不能自动替代用户已有的封面选择。
5. 检查标题、正文开头/末尾、链接、格式、正文图片顺序与数量，确认没有 `XIMGPH_` 残留。表格、代码块等在网页编辑器中的实际粘贴效果要检查；不支持时明确指出，保留现场，不私自重写或删除。

## 保存确认

只停留在草稿，不能点击 Publish/Post。等待编辑器已保存状态，返回草稿列表，再重新打开该草稿；复核完整正文和所有图片均存在。若页面未能提供保存信号且无法重新打开，就报告“内容已填入，尚未确认保存”，不能报告成功。

记录实际观测到的账号和草稿编辑 URL，不猜 URL 格式。失败时保留当前编辑器现场与准备文件以便继续，不重新创建一篇。成功后删除本次 prepare 生成的临时文件，不动原笔记和附件。

本路线参考了 [baoyu-post-to-x](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-post-to-x) 的富文本＋图片占位符思路；没有复制或捆绑上游脚本。X 的页面选择器未写死在本包中，由宿主 Agent 基于实时页面处理。首次真实投递需要在目标宿主与账号验收。
